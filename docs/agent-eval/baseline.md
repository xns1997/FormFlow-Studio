> 以下为 2026-08-04 真实 mimo-v2.5 实测基线（default-cloud）。

## 基线（2026-08-04）

| 任务 | 结果 | 耗时 | 模型/工具调用 | 无效工具 | 暂停 | 恢复/压缩 | token | 失败 |

| 双表+表单+批量只读+回归 | ✅ completed 5/5 | 172s | 9 / 8 | 0 | 0 | 0 / 0 | 109,089 | 0 |

三轮全部零问题。期间发现并修复的问题（已进入代码）：

1. mimo 支持原生 `response_format: json_schema`：openai_compatible 适配器优先原生结构化输出，端点不支持时回退提示词模式；智能体调用默认 `max_tokens=2048`，避免推理 token 吃光预算。
2. 幂等创建（资源已存在）只记一条成功观察，不再先记失败再记成功。
3. 写任务自动收尾仅限「写工具成功 + 确定性验收通过」，避免只读成功误验收；交付物检查兼容「创建 department 数据表」这类 id 前置写法，并识别控件/绑定/行数据/空表语义。
4. 质量门禁按计划作用域过滤无关阻塞项（如数据计划不因「尚未配置表单」阻塞）；测试类阻塞由独立测试门禁区分预存/引入。
5. 决策同时给 toolName 与 batchReads 时自动归一化（批量全只读→执行批量，否则执行单工具），不再浪费一步。
6. 被拒绝/失败的写尝试不再重置只读计数，保证「资源已存在」类配置任务能被自动验收解除卡死。
7. 规划器去重引导：建表任务可一步设置主键与行数据时，不再拆分「配置主键」「写入示例数据」冗余任务；任务 id 统一小写 t 前缀。
8. 上下文压缩估算只统计实际注入 Prompt 的内容（最近消息/观察/摘要），不再因事件流增长每步空转。

## 能力探针结论（2026-08-04）

- 结构化 JSON：mimo 支持原生 `response_format: json_schema`（响应快、无推理空转）；prompt 模式也能输出合法 JSON。
- 长上下文稳定性：~17k token 的决策提示稳定输出；压缩阈值已按实际 Prompt 估算修正。
- 原生工具调用：mimo 返回 `tool_calls: null`（不原生支持函数调用），决策保持结构化 JSON 主路径，native tool calling 保持关闭。

## 验收目标（基线后冻结）

- 一次完成率 ≥80% 或较基线 +15pp（取更严）——本轮 3/3 场景一次完成
- 无进展暂停 ≤1 次/写任务——本轮 0
- 无效工具调用比 ≤15%——本轮 0%
- 写计划完成前测试执行率 100%——本轮 3/3 场景均执行 `project_test.run`
