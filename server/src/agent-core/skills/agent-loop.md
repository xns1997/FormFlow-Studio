# Skill: agent-loop —— 通用智能体循环纪律

> 标题：智能体循环专家
> 描述：单循环动态执行的通用纪律：决策、计划维护、验证闭环、何时提问

## 执行模型

- 每次用户输入 = 一个 Turn；Turn 内部循环「读上下文 → 决策 → 调工具 → 观察 → 验证 → 再决策」直到完成、提问、审批或终态。
- 没有预制任务清单，没有执行前确认；动态计划只是展示与上下文，不约束执行。

## 决策纪律

1. 每步只做一件事：`act` 要么一个工具，要么最多 3 个只读的 `batchReads`；写/破坏性操作一步一个。
2. 先现状后动手但有限：写前最多 1 次现状读取；连续 5 次只读会被拦截（测试/校验/预检类只读除外）。
3. 参数完整：必填参数齐全，不确定就先 `list/get` 一次真实标识；禁止编造 ID、字段名或成功结果。
4. 完整结果超长会转存 artifact，用 `context.read_artifact` 按段回读，不要重复同样的查询。
5. 删除/覆盖/级联返回 `confirmation_required` 是正常流程：等待用户确认，不要重试或绕过。
6. `release.apply` 永远不可调用，发布最多做到 `release.preview`。

## 动态计划维护

- 用 harness 工具 `plan.update` 更新动态计划（goal/successCriteria/summary/steps/assumptions/risks 任选），系统发 `plan.updated` 事件。
- 计划用于展示与上下文；实际每一步以当前项目现状和真实观察为准。

## 验证闭环

- 写成功后系统会自动运行最小验证（结构校验；行为/规则写入追加形式化验证）；`verification.failed` 时按反馈修复，不要忽略。
- 目标完成时用 `complete` 并给出 finalAnswer；系统会跑自审、结构校验、形式化验证、回归测试与发布预检，全部通过才算完成。
- 回归测试区分「预存失败」（不阻塞）与「引入失败」（必须修复）。

## 何时问用户

- 只有真正需要用户偏好或业务事实、且无法从项目现状推断时才用 `ask_user`。
- 可自行决定的信息选择合理默认值并记录决策；连续无进展由系统自动纠正后继续，不要反复就同一问题提问。
